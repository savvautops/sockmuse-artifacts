How the A1 pool splits: one A1 can use the full 2 OCPUs / 12 GB, as your planned VM does. If you
want two A1 VMs, they must divide that same pool, for example 1 OCPU / 6 GB each. The pool was
reduced from 4 OCPUs / 24 GB in June 2026.

Storage determines how many fit
All boot and block volumes share 200 GB total. OCI boot volumes have a 47 GB minimum. Four minimumsize boot volumes need about 188 GB. Your 100 GB boot volume leaves 100 GB, enough for two more 47 GB
boot volumes, so the practical maximum with the current disk choice is three VMs total, not four.

Where your VM wins: 55% more RAM, over 13 times the disk, and dedicated physical CPU cores. It is
built to stay online and host your own services.

Where the sandbox differs: x86_64 has broader compatibility with old or x86-only binaries. On the A1
VM, prefer packages and container images that publish linux/arm64 builds.

The “brain” is separate from the hardware. The VM runs the installed agent, command-line
interfaces, orchestration, storage, and networking. API keys let those tools call remote large language
models; the model inference usually runs at the API provider, not on the two Arm cores.

04 / CREATE THE VM

A safe starter configuration

Build one simple, recoverable server
1

Name and placement
Open Compute › Instances › Create instance. Use nelson-vm-01 . Confirm the compartment and
the Montreal home region ( ca-montreal-1 ).

2

Choose the image
Select Canonical Ubuntu 24.04 Minimal aarch64 for A1. If you choose Oracle Linux, remember the
SSH user changes from ubuntu to opc .

3

Choose the shape
Select VM.Standard.A1.Flex , then set 2 OCPUs / 12 GB RAM. Stop if the page does not show the
shape as Always Free eligible.

4

Create the network path
Use a VCN with a public subnet, internet gateway, and route to 0.0.0.0/0 . Assign a public IPv4
address if you need direct SSH from home.

5

Use an SSH public key
Upload an existing .pub key or let OCI generate a key pair. Download the private key once and store it
securely. Oracle does not retain a recoverable copy of a console-generated private key.

6

Keep storage modest
Use the selected 100 GB boot volume. It leaves 100 GB in the Always Free storage pool; every
additional instance needs at least 47 GB.

7

Review before launch
Confirm the Always Free label, architecture, OCPU/RAM, boot size, public IP choice, and estimated
cost. Then create the instance and wait for Running.

05 / FIRST CONNECTION

SSH, patch, verify

Your first ten minutes on the VM
1. Lock down the key locally
chmod 600 ~/keys/oracle-vm.key

2. Connect to the public IP
# Ubuntu image
ssh -i ~/keys/oracle-vm.key ubuntu@203.0.113.10
# Oracle Linux image
ssh -i ~/keys/oracle-vm.key opc@203.0.113.10
Replace the example address with the instance's real public IP. On first connection, verify the host-key fingerprint through a
trusted channel before accepting it.

3. Identify and update the system
uname -m
# A1 normally reports aarch64
cat /etc/os-release
sudo apt update && sudo apt upgrade -y
# Ubuntu
# Oracle Linux: sudo dnf upgrade -y

4. Check resources
nproc
free -h
lsblk
df -h /
ip -brief address

# logical processors visible to Linux
# memory
# disks and mount points
# root filesystem usage
# interfaces and addresses

5. Create a memorable local SSH alias
# ~/.ssh/config on your own computer
Host oracle-free
HostName 203.0.113.10
User ubuntu
IdentityFile ~/keys/oracle-vm.key
IdentitiesOnly yes
# Then connect with:
ssh oracle-free

Never lose the private key. Keep an encrypted backup. Anyone who gets it can attempt to access the
server; Oracle's documentation says it cannot recover a console-generated private key for you.
File transfer: use scp local-file oracle-free:~/ to upload, or scp -r oracle-free:~/folder ./ to
download.

When SSH does not connect, check in this order
1. Lifecycle: the instance is Running, not Stopped, Terminated, or Provisioning.
2. Address: use the current public IP shown on the instance details page.
3. Network: public subnet, internet-gateway route, and TCP 22 ingress are present.
4. Source: if port 22 is limited to a /32 , your current home public IP still matches it.
5. Username: ubuntu for Ubuntu; opc for Oracle Linux and Red Hat-compatible images.
6. Key: the private key matches the public key installed at creation, and local permissions are restrictive.
7. Syntax: use ssh -i /path/key user@public-ip .
Useful SSH diagnostics:
ssh -vvv -i ~/keys/oracle-vm.key ubuntu@203.0.113.10
# timeout: usually route/firewall/address
# permission denied (publickey): usually user/key mismatch

When an app works locally but not remotely
curl -I http://127.0.0.1:PORT
sudo ss -lntup | grep PORT
sudo ufw status verbose
# Then check the OCI NSG/security-list ingress rule for the same port.

Idle reclamation changes the design. Oracle may reclaim an Always Free compute instance it
