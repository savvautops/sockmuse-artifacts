OCI is a set of nested boundaries

Identity and organization

Tenancy: the top-level account and billing boundary.

Identity domain: users, sign-in, groups, and authentication.

Compartment: a logical container used for permissions, quotas, budgets, and finding resources.

OCID: Oracle Cloud Identifier, a long unique ID attached to each resource.

Compute and storage

Instance: a virtual machine.

Shape: CPU architecture, OCPU count, and memory profile.

Image: operating system template, such as Ubuntu or Oracle Linux.

Boot volume: persistent disk holding the operating system and files.

Location

Home region: the account's anchor region. Always Free compute must be created here.

Availability domain (AD): an isolated data-center group within a region.

Fault domain: a hardware grouping inside an AD.

Networking

VCN: your software-defined private network.

Subnet: a slice of the VCN address space.

Internet gateway: a route target that lets a public subnet reach the internet.

NSG: Network Security Group; firewall rules for selected VNICs.

Fast orientation: check the region selector, then the compartment selector, before assuming a resource is missing.

02 / Always FreeHow many VMs you actually get

You can run up to four free VMs

As of September 2026, an Always Free tenancy can hold up to four compute instances: as many as two Ampere A1 Flex VMs sharing one Arm resource pool, plus two AMD E2.1.Micro VMs.

A1 Flex allowance
2 VMs

They share 2 OCPUs and 12 GB RAM across the tenancy.

E2 Micro allowance
2 VMs

Each has 1 AMD OCPU, 2 vCPUs, and 1 GB RAM.

Maximum count
4 VMs

Only if the shared 200 GB disk pool can hold all boot volumes.

The four slots are not identical

Free allowanceCPURAMBest use
Up to 2 × A1 FlexAmpere Altra Arm; 2 OCPUs total shared12 GB total sharedMain app server, Docker, agents, Node/Python workloads
2 × E2.1.MicroAMD x86; 1 OCPU = 2 vCPUs each via hyperthreading1 GB eachLight bot, status page, proxy, tiny sidecar
How the A1 pool splits: one A1 can use the full 2 OCPUs / 12 GB, as your planned VM does. If you want two A1 VMs, they must divide that same pool, for example 1 OCPU / 6 GB each. The pool was reduced from 4 OCPUs / 24 GB in June 2026.

Storage determines how many fit

All boot and block volumes share 200 GB total. OCI boot volumes have a 47 GB minimum. Four minimum-size boot volumes need about 188 GB. Your 100 GB boot volume leaves 100 GB, enough for two more 47 GB boot volumes, so the practical maximum with the current disk choice is three VMs total, not four.

Other free infrastructure

  • 10 TB outbound bandwidth each month
  • Public IPv4 is free while attached to a running instance
  • 200 GB combined boot/block storage

Two important caveats

  • Arm capacity can be scarce: retry after Out of host capacity, or try another available region.
  • Oracle may reclaim Always Free instances it classifies as idle.

04 / Create the VMA safe starter configuration

Build one simple, recoverable server

Name and placement

Open Compute › Instances › Create instance. Use nelson-vm-01. Confirm the compartment and the Montreal home region (ca-montreal-1).

Choose the image

Select Canonical Ubuntu 24.04 Minimal aarch64 for A1. If you choose Oracle Linux, remember the SSH user changes from ubuntu to opc.

Choose the shape

Select VM.Standard.A1.Flex, then set 2 OCPUs / 12 GB RAM. Stop if the page does not show the shape as Always Free eligible.

Create the network path

Use a VCN with a public subnet, internet gateway, and route to 0.0.0.0/0. Assign a public IPv4 address if you need direct SSH from home.

Use an SSH public key

Upload an existing .pub key or let OCI generate a key pair. Download the private key once and store it securely. Oracle does not retain a recoverable copy of a console-generated private key.

Keep storage modest

Use the selected 100 GB boot volume. It leaves 100 GB in the Always Free storage pool; every additional instance needs at least 47 GB.

Review before launch

Confirm the Always Free label, architecture, OCPU/RAM, boot size, public IP choice, and estimated cost. Then create the instance and wait for Running.

Open only what you use

  • TCP 22: SSH, ideally from your own public IP
  • TCP 80: HTTP, if serving a public website
  • TCP 443: HTTPS, if serving a public website

Do not do this

  • Do not paste a private SSH key into cloud-init.
  • Do not enable password SSH for convenience.
  • Do not expose databases or admin panels to 0.0.0.0/0.
Arm compatibility check: before deploying a container, look for a multi-architecture image or explicit linux/arm64 support. Run uname -m; A1 should report aarch64.

05 / First connectionSSH, patch, verify

Your first ten minutes on the VM

1. Lock down the key locally

chmod 600 ~/keys/oracle-vm.key

2. Connect to the public IP

# Ubuntu image
ssh -i ~/keys/oracle-vm.key ubuntu@203.0.113.10

# Oracle Linux image
ssh -i ~/keys/oracle-vm.key opc@203.0.113.10

Replace the example address with the instance's real public IP. On first connection, verify the host-key fingerprint through a trusted channel before accepting it.

3. Identify and update the system

uname -m                 # A1 normally reports aarch64
cat /etc/os-release
sudo apt update && sudo apt upgrade -y   # Ubuntu
# Oracle Linux: sudo dnf upgrade -y

4. Check resources

nproc                    # logical processors visible to Linux
free -h                  # memory
lsblk                    # disks and mount points
df -h /                  # root filesystem usage
ip -brief address        # interfaces and addresses

5. Create a memorable local SSH alias

# ~/.ssh/config on your own computer
Host oracle-free
  HostName 203.0.113.10
  User ubuntu
  IdentityFile ~/keys/oracle-vm.key
  IdentitiesOnly yes

# Then connect with:
ssh oracle-free
Never lose the private key. Keep an encrypted backup. Anyone who gets it can attempt to access the server; Oracle's documentation says it cannot recover a console-generated private key for you.

File transfer: use scp local-file oracle-free:~/ to upload, or scp -r oracle-free:~/folder ./ to download.

A public IP alone does not open a port

Inbound traffic works only when every relevant layer permits it and the application is actually listening.

LayerQuestionWhere to check
Public addressDoes the primary VNIC have a public IP?Instance › Networking › Attached VNICs
Route tableDoes the subnet route internet traffic to an internet gateway?VCN › Subnets › Route table
Cloud firewallDoes an ingress rule allow the protocol, port, and source?NSG or subnet security list
Host firewallDoes Linux permit the port?sudo ufw status or firewalld
ApplicationIs something listening on the correct interface?sudo ss -lntup

Security list

Rules apply to all VNICs in the associated subnet. Simple, but broad.

Network Security Group

Rules apply only to selected VNICs. Oracle recommends NSGs for separating application security from subnet design.

Source CIDR: choose the narrowest safe value

SourceMeaningUse
your.public.ip/32One IPv4 addressBest for SSH when your address is stable
0.0.0.0/0Every IPv4 addressNormal for public HTTP/HTTPS; risky for admin ports
VCN CIDRPrivate network onlyInternal services between OCI resources
Two-firewall trap: adding an OCI ingress rule does not update Ubuntu's UFW or Oracle Linux's firewalld. Check both. Also bind public services to 0.0.0.0 or the VM's private address, not only 127.0.0.1.

When SSH does not connect, check in this order

  1. Lifecycle: the instance is Running, not Stopped, Terminated, or Provisioning.
  2. Address: use the current public IP shown on the instance details page.
  3. Network: public subnet, internet-gateway route, and TCP 22 ingress are present.
  4. Source: if port 22 is limited to a /32, your current home public IP still matches it.
  5. Username: ubuntu for Ubuntu; opc for Oracle Linux and Red Hat-compatible images.
  6. Key: the private key matches the public key installed at creation, and local permissions are restrictive.
  7. Syntax: use ssh -i /path/key user@public-ip.
Useful SSH diagnostics:
ssh -vvv -i ~/keys/oracle-vm.key ubuntu@203.0.113.10
# timeout: usually route/firewall/address
# permission denied (publickey): usually user/key mismatch

When an app works locally but not remotely

curl -I http://127.0.0.1:PORT
sudo ss -lntup | grep PORT
sudo ufw status verbose
# Then check the OCI NSG/security-list ingress rule for the same port.

08 / GuardrailsFree, secure, recoverable

Treat free infrastructure as replaceable

Cost controls

  • Create a small monthly budget with email alerts.
  • Check Cost Analysis after creating resources.
  • Verify every shape and service is Always Free eligible.
  • Delete unused paid resources, not only their parent VM.
  • Remember: a budget is an alerting tool, not a hard spending cap.

Access controls

  • Keep multifactor authentication enabled for the cloud account.
  • Use SSH keys; keep password login and root login disabled.
  • Restrict SSH ingress to your IP or a private overlay network.
  • Patch the OS and applications regularly.
  • Never store private keys, API keys, or tokens in a public repo.

Budget setup

Open Billing & Cost Management › Budgets and create a budget scoped to the root or project compartment.

Add actual-spend alert rules at low thresholds appropriate for a free-tier account.

Send alerts to an address you actively monitor, then verify the alert rule exists.

Idle reclamation changes the design. Oracle may reclaim an Always Free compute instance it classifies as idle. Do not manufacture fake load. Instead, keep important code in source control, back up stateful data, and make the server reproducible so a replacement is routine.

Minimum backup pattern

WhatWhereCadence
Application codePrivate Git repositoryEvery meaningful change
ConfigurationEncrypted backup; secrets separateAfter configuration changes
Database/dataEncrypted off-instance destinationBased on acceptable data loss
Boot volumeOCI boot-volume backupBefore risky upgrades or migrations
Recovery test: a backup is not proven until you can restore it. Keep a short rebuild note: image, shape, ports, DNS, packages, services, mount points, and restore command.

09 / ReferenceGlossary + official sources

The one-page memory card

Provisioning words

Tenancy: your whole OCI account.

Region: geographic deployment area.

Compartment: logical resource and policy container.

Shape: VM CPU architecture and resource profile.

Image: operating system template.

OCID: globally unique Oracle resource ID.

Networking words

VCN: virtual cloud network.

Subnet: address range inside a VCN.

VNIC: virtual network interface card.

NSG: firewall rules for selected VNICs.

Security list: firewall rules for a subnet.

CIDR: compact notation for an IP range.

Recommended starter: one Ubuntu LTS Arm VM on VM.Standard.A1.Flex, 2 OCPUs, 12 GB RAM, 100 GB boot volume, reserved public IP, key-based SSH, TCP 22, and public TCP 80/443 for web traffic.
