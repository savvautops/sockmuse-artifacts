01 / Mechanics

LoRA trains the delta, not the whole model

Low-Rank Adaptation (LoRA) freezes the pretrained model and learns small update matrices beside selected linear layers. The original weights stay intact.

Frozen weight W+Low-rank A × B=Role behavior

LoRA

  • The base model normally remains in FP16 or BF16 during training.
  • Only adapter parameters receive gradient updates.
  • The saved adapter is usually tens to hundreds of megabytes, depending on model size, rank, and target modules.
  • At inference, load it beside the matching base or merge it into a standalone model.

QLoRA

  • The frozen base is loaded in 4-bit form.
  • LoRA parameters still train at a higher working precision.
  • Memory drops enough to make 4B to 8B experiments practical on modest GPUs.
  • The quality tradeoff is normally smaller than full low-bit training because the base remains frozen.
The mental model: the base carries language and general capability. The adapter nudges behavior, format, vocabulary, and task patterns. It is not a reliable database of current facts.

What the key settings control

SettingMeaningStarting point
rCapacity of each low-rank update16
lora_alphaScale applied to the update16
target_modulesLinear layers that receive adaptersAttention + MLP projections
load_in_4bitQuantizes the frozen baseTrue

02 / Model selection

Standardize the fleet on one base checkpoint

A LoRA adapter is tied to the architecture and usually the exact base checkpoint it was trained against. A Qwen adapter does not load on Llama, and even a nearby revision can break tensor names or behavior.

CandidateBest first usePractical training note
Qwen3-4B InstructFast pipeline proof, tool or role behaviorEasy starting point on 12 to 16 GB
Qwen3-8BHigher-quality role adapter after proofStart micro-batch 1 or 2 at 2,048 tokens
Llama 3.1 8B InstructLlama ecosystem compatibilityLicense terms and gated access may apply

Hardware planning

TargetSuggested workloadStarting values
Kaggle T4, 16 GB4B to 8B QLoRAbatch 2, accumulation 4
Kaggle P100, 16 GB4B to 8B if the software stack supports Pascalverify CUDA capability first
Local RTX 3060, 12 GB4B comfortably, 7B to 8B carefullybatch 1 to 2, checkpointing on
Hardware name: the 12 GB card is the NVIDIA GeForce RTX 3060, not GTX 3060. For an 8B run, batch 2 to 4 is only realistic when sequence length, packing, and data shape cooperate. Start at 1 or 2, then increase after measuring peak VRAM.

Decision rule

  1. Choose the smallest instruct model that can pass your baseline tasks.
  2. Record the exact model repository and revision in every adapter manifest.
  3. Keep tokenizer, chat template, and base revision identical at training and inference.

03 / Data

The dataset decides what the adapter becomes

For a narrow role adapter, 5,000 to 20,000 clean instruction-response pairs is a sensible working range, not a guarantee. Diversity, correctness, and coverage matter more than row count.

Source mix

  • Public-domain corpora: use only material whose license and provenance you can record.
  • Existing instruction sets: verify task fit and redistribution terms.
  • Synthetic examples: generate cheaply with DeepSeek, then filter, deduplicate, and review samples.

Split before tuning

  • Reserve 10 percent for evaluation.
  • Keep near-duplicates in the same split.
  • Create a separate challenge set for edge cases and refusals.
  • Never tune against the final certification exam.

Alpaca JSONL

One JSON object per line, UTF-8, with instruction, optional input, and output.

{"instruction":"Summarize the clause in plain language.","input":"The license terminates upon material breach...","output":"The license can end if a serious breach is not fixed under the agreement's cure terms."}
{"instruction":"Ask the missing questions before answering.","input":"Can I terminate this contract?","output":"Which jurisdiction governs, what termination clause applies, and has either party breached?"}
{"instruction":"Decline a request outside the role.","input":"Guarantee I will win this case.","output":"I cannot guarantee an outcome. I can help identify issues and questions to discuss with a licensed lawyer."}

Quality gates before training

  • Parse every line as JSON and require non-empty instruction and output.
  • Normalize whitespace, remove exact duplicates, and hash rows for traceability.
  • Scan for secrets, personal data, prompt injection, and unlicensed copied text.
  • Manually inspect a random sample from every source and category.
  • Store source_id, license, generator model, and review status outside the training text.

04 / Kaggle setup

Authenticate once, then run Kaggle as a batch backend

Kaggle CLI authentication is token-based, not OAuth, for this workflow. The legacy kaggle.json contains a username and API key, so treat it as a secret.

Create the token

In Kaggle, open Settings, find API, choose Create New Token, and download kaggle.json. Do not paste its contents into chat, source control, or notebook cells.

Install it on the machine that runs the CLI

mkdir -p ~/.kaggle
install -m 600 /path/to/downloaded/kaggle.json ~/.kaggle/kaggle.json
python -m pip install --upgrade kaggle
kaggle --version

Verify without changing anything

kaggle kernels list --mine | head
Credential rule: add .kaggle/, kaggle.json, and environment files to ignore rules. Rotate the token if it reaches a repository, notebook output, log, or shared drive.

Budget the run

Free-tier quotas and session ceilings change. A practical planning assumption is roughly 30 GPU-hours per week and a run that must finish within about 9 hours. Check the current Kaggle account quota before launching. Enable Internet only when the notebook must install packages or fetch models.

05 / Training script, part 1

Load 4-bit Qwen and format every example with its chat template

In a Kaggle script kernel, install dependencies before imports. On local CUDA, install the matching stack once in the environment instead.

# Kaggle only, place before imports
import subprocess, sys
subprocess.check_call([
    sys.executable, "-m", "pip", "install", "-qU",
    "unsloth", "datasets", "trl", "accelerate"
])
import os, torch
from datasets import load_dataset
from unsloth import FastLanguageModel, is_bfloat16_supported

MODEL = os.getenv(
    "MODEL_ID",
    "unsloth/Qwen3-4B-Instruct-2507-unsloth-bnb-4bit",
)
DATA_PATH = os.getenv("DATA_PATH", "train.jsonl")
OUTPUT = "/kaggle/working/role-lora" if os.path.exists("/kaggle") \
         else "./role-lora"
MAX_SEQ = int(os.getenv("MAX_SEQ_LENGTH", "2048"))

model, tokenizer = FastLanguageModel.from_pretrained(
    model_name=MODEL,
    max_seq_length=MAX_SEQ,
    dtype=None,
    load_in_4bit=True,
)

model = FastLanguageModel.get_peft_model(
    model,
    r=16,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                    "gate_proj", "up_proj", "down_proj"],
    lora_alpha=16,
    lora_dropout=0,
    bias="none",
    use_gradient_checkpointing="unsloth",
    random_state=3407,
)

05 / Training script, part 2

Format the dataset and define the training run

from trl import SFTTrainer, SFTConfig

def to_text(row):
    user = row["instruction"]
    if row.get("input", "").strip():
        user += "\n\nContext:\n" + row["input"].strip()
    messages = [
        {"role": "user", "content": user},
        {"role": "assistant", "content": row["output"]},
    ]
    return {"text": tokenizer.apply_chat_template(
        messages, tokenize=False, add_generation_prompt=False
    )}

data = load_dataset("json", data_files=DATA_PATH, split="train")
data = data.map(to_text)
splits = data.train_test_split(test_size=0.10, seed=3407)

args = SFTConfig(
    output_dir=OUTPUT,
    dataset_text_field="text",
    max_length=MAX_SEQ,
    per_device_train_batch_size=2,
    per_device_eval_batch_size=2,
    gradient_accumulation_steps=4,
    num_train_epochs=1,
    learning_rate=2e-4,
    warmup_ratio=0.03,
    logging_steps=10,
    eval_strategy="steps",
    eval_steps=100,
    save_strategy="steps",
    save_steps=100,
    save_total_limit=2,
    optim="adamw_8bit",
    weight_decay=0.01,
    lr_scheduler_type="linear",
    fp16=not is_bfloat16_supported(),
    bf16=is_bfloat16_supported(),
    packing=True,
    report_to="none",
    seed=3407,
)

05 / Training script, part 3

Train, evaluate, and save the adapter

trainer = SFTTrainer(
    model=model,
    processing_class=tokenizer,
    train_dataset=splits["train"],
    eval_dataset=splits["test"],
    args=args,
)

trainer.train()
metrics = trainer.evaluate()
print(metrics)

model.save_pretrained(OUTPUT + "/adapter")
tokenizer.save_pretrained(OUTPUT + "/adapter")

Smoke-test before spending hours

  1. Temporarily train on 20 to 100 rows.
  2. Confirm loss is finite and generally moving down.
  3. Confirm evaluation executes and an adapter is written.
  4. Reload the saved adapter against the exact base model.
  5. Only then launch the complete dataset.
Version drift: TRL occasionally renames configuration arguments. If max_length or eval_strategy is rejected, inspect python -c "from trl import SFTConfig; help(SFTConfig)" in that exact environment, then change only the rejected field.
Effective batch: micro-batch 2 multiplied by accumulation 4 gives an effective batch of 8 examples per optimizer update on one GPU.

07 / VRAM survival

Reduce sequence memory before reducing adapter capacity

When an 8B run fails on 12 GB, make one change at a time in this order.

  1. Drop micro-batch to 1. Preserve the effective batch with more gradient accumulation.
  2. Shorten sequence length. Move from 2,048 to 1,536 or 1,024. Attention memory grows rapidly with sequence length.
  3. Keep gradient checkpointing on. "unsloth" trades extra compute for lower activation memory.
  4. Use the 8-bit optimizer. Keep optim="adamw_8bit".
  5. Disable evaluation during the smoke run. Restore it for the real run.
  6. Only then lower rank. Try r=8 if capacity is still too expensive.

Known-good starting grid

ModelSequenceMicro-batchAccumulation
Qwen3-4B2,0482 to 42 to 4
Qwen3-8B2,0481 to 24 to 8
8B, OOM fallback1,02418 to 16
Do not promise runtime from row count alone: 10,000 examples could mean 2 million or 20 million tokens. Run 100 steps, record seconds per step, include evaluation and saving overhead, then estimate. “A few hours” is plausible for a tuned 8B run, not guaranteed.

08 / Export

Keep the adapter as the source artifact

The PEFT adapter is the smallest, most flexible deliverable. Preserve it even if you also produce a merged model or GGUF.

Option A, publish the adapter to Hugging Face Hub

# Authenticate without putting the token in source
hf auth login

# In Python, after training
model.push_to_hub("YOUR_USER/qwen3-role-lora")
tokenizer.push_to_hub("YOUR_USER/qwen3-role-lora")

Option B, export a standalone GGUF for LM Studio

# In Python, merges the active adapter for a standalone file
model.save_pretrained_gguf(
    "./role-model-gguf",
    tokenizer,
    quantization_method="q4_k_m",
)

Import the resulting GGUF into LM Studio. Use the same chat template used during training; a mismatch can make a good adapter look broken.

Option C, hot-swap the adapter

# Convert a PEFT adapter with the current llama.cpp converter
python /path/to/llama.cpp/convert_lora_to_gguf.py \
  ./role-lora/adapter --outfile ./role-lora.gguf

# Run beside the matching base GGUF
llama-cli -m ./matching-base.gguf --lora ./role-lora.gguf
# vLLM serves PEFT adapters beside the matching Hugging Face base
python -m vllm.entrypoints.openai.api_server \
  --model YOUR_EXACT_BASE_ID \
  --enable-lora \
  --lora-modules role=./role-lora/adapter
Choose deliberately: adapter for reuse and hot-swap, merged GGUF for a single-file local app, Hub repository for sharing and versioning. Record the base ID in all three.

09 / Evaluation

A lower training loss is not a release decision

Compare the adapter with the untouched base on examples neither model saw during training.

Minimum release gate

CheckMeasurePass condition
Held-out lossEvaluation splitPlateaus or improves without divergence
Task scoreExact or rubric scoreBeats the base on target tasks
Regression setGeneral instructionsNo material capability collapse
Open-ended qualityBlind human rubricStable preference over base
Safety / boundariesAdversarial promptsRequired refusals and escalation hold

Human-judge agreement

For open-ended work, have two reviewers score a sample using the same rubric. Track agreement, adjudicate disagreements, and update the rubric before changing the model. An LLM judge can accelerate triage, but calibrate it against human labels.

When to stop

  • Stop when evaluation loss plateaus while training loss keeps falling.
  • Stop when target-task gains flatten across checkpoints.
  • Stop immediately if general-task regressions or unsafe confident answers increase.
  • Keep the best checkpoint by evaluation result, not automatically the last checkpoint.
Certification rule: training data, development prompts, and the final Agent School exam must be separate. Otherwise the certificate measures memorization.

11 / Worked example

A lawyer-role adapter needs retrieval, boundaries, and human review

Use the adapter to shape legal issue-spotting, plain-language explanation, drafting structure, and uncertainty behavior. Do not use it as the source of current law.

Training mix

60 percent

Legal instruction pairs

Issue spotting, clause explanation, question generation, memo structure, and jurisdiction-aware analysis.

20 percent

Boundaries and refusal

“I am not a licensed attorney,” missing-fact questions, no outcome guarantees, emergency escalation.

20 percent

General instruction

Retain ordinary following, summarization, formatting, and tool-use behavior.

Inference architecture

User question→jurisdiction filter→verified legal RAG→role adapter→citations + review
  • Retrieval supplies facts: statutes, regulations, cases, effective dates, and source URLs.
  • The adapter supplies behavior: analysis pattern, tone, structured output, and boundary responses.
  • The application verifies citations: reject any citation not present in retrieved sources.
  • A licensed professional reviews consequential output: especially filings, deadlines, strategy, and jurisdiction-specific advice.
Known failure mode: a fluent legal model can invent plausible case names and holdings. LoRA cannot solve that. Require source-grounded generation and a fail-closed citation checker.
